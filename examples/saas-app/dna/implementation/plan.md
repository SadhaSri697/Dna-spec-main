# Implementation Plan

> Auto-generated by the dna-spec skill from the DNA.

## Strategy

Top-down with a thin vertical slice first. M1 lands the foundation
(database, auth scaffolding, deploy pipeline, observability). M2
brings auth and team-management to life. M3 implements the standup
loop, which is the product's reason to exist. M4 polishes: settings,
edge cases, and operational concerns.

## Build order rationale

Auth must work before anything user-facing. Teams must work before
the standup loop can be scoped. The standup loop is the product's
core value, so it goes early in the milestone sequence, not late.
Polish and edge cases come after the core loop is verifiable.

## Cross-cutting concerns

- **Email service**: needed by M2 (verification), M3 (prompts and
  digests). Set up in M1.
- **Scheduling**: needed by M3 for daily and weekly jobs. Set up
  in M1.
- **Observability**: structured logs, metrics, and traces from M1
  onward. Required by the operational requirements.
- **Auth middleware**: needed by M2 onward. Set up in M1.

## Deferred

- Magic link login (v2) — currently, password only
- SSO / SAML (v2) — out of scope
- Multi-team membership per user (v2) — current is one team per
  user

## Out of scope

Reference `dna/vision.md` non-goals:

- Project management (no tickets, no sprints)
- 1:1 meeting facilitation
- Cross-team standups
