# Implementation Plan

> Auto-generated by the dna-spec skill from the DNA.

## Strategy

Hot path first. The redirect endpoint is the product's reason to
exist; it gets the most attention. M1 sets up the foundation.
M2 lands the link CRUD plus the redirect endpoint. M3 adds the
analytics pipeline and the stats endpoints.

## Build order rationale

The redirect cannot exist without links. Links cannot exist
without schema. Schema is M1. The redirect is M2. Stats come
after the redirect is producing events, which is M3.

### M2: Links API

**Goal**: Authenticated users can create, list, and delete
links. The redirect endpoint resolves slugs.

**Scope**:
- Domain(s): links, redirect (resolve only)
- Feature(s): create-link, list-links, resolve-link

### M3: Redirect & Analytics

**Goal**: Click tracking is wired in. Stats endpoints return
real data.

**Scope**:
- Domain(s): redirect (track click), analytics
- Feature(s): track-click, click-stats, time-series
- Flow(s) covered: link-sharing (full), analytics-deep-dive

**Depends on**: M2

**Tasks**: T-009 .. T-011 (3 tasks)

**Exit criterion**:
- A click on `/{slug}` results in a click event being emitted

- Stats are eventually consistent (visible within 5 minutes)

## Cross-cutting concerns

- **Auth**: API-key based, applied via middleware. Set up in
  M1; used by M2 and M3.
- **Rate limiting**: per-key limits, set up in M2.
- **Click event queue**: in-process queue with backpressure,
  set up in M2; consumed in M3.
- **Analytics rollup**: daily aggregation job, set up in M3.
